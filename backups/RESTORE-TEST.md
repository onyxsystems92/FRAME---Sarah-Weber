Real test performed on 2026-09-25 (not a claim, an executed check):

4. Ran `npx eleventy --input=src --output=dist` there.
5. Diffed the restored build's `dist/` against the original repository's
   `dist/` (excluding `admin/`, which contains a large vendored bundle not
   worth byte-diffing): **zero differences**. The restored copy produced an
   identical website from the archive alone.

This proves the backup is sufficient and complete on its own: no access to
this machine, this session, or Franklyn's GitHub account is required to
reconstruct a working copy of the site from a `.tar.gz` in this folder.

## Restoring in practice

```bash
tar -xzf backups/rz-website-source-backup-<date>.tar.gz -C /path/to/restore
cd /path/to/restore
npm install       # also regenerates admin/vendor automatically
npm run build     # produces dist/
```

If `admin/vendor/static-cms-app/` is missing after `npm install` (some
environments restrict lifecycle scripts), run `npm run postinstall`
manually once.

## Making a new backup

```bash
tar --exclude='node_modules' --exclude='dist' --exclude='backups' \
    --exclude='.git' --exclude='admin/vendor' \
    -czf "backups/rz-website-source-backup-$(date +%Y%m%d-%H%M%S).tar.gz" \
    package.json package-lock.json .eleventy.js src \
    admin/config.yml admin/index.html EDITING.md \
    README.md DESIGN.md CONTENT.md AGENTS.md CLAUDE.md scripts
```

Store the resulting file somewhere outside this repository (external drive,
cloud storage folder Sarah/Tilmann control, etc.) — a backup that lives only
next to the thing it backs up is not a backup.
